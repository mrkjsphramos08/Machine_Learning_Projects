# Project 01 — Diabetes Progression Regression

Predicting disease progression one year after baseline from 10 baseline
variables, using the **scikit-learn diabetes dataset** that was bundled with the
original scaffold.

| Property | Value |
| :--- | :--- |
| Source | `sklearn.datasets.load_diabetes()` (saved to `data/raw/data.csv`, tracked by DVC) |
| Rows | 442 |
| Features | 10 (`age`, `sex`, `bmi`, `bp`, `s1`–`s6`), already mean-centred and scaled |
| Target | `target` — continuous, 25 to 346 |
| Task | Regression |
| Primary metric | RMSE (lower is better) + R² |

---

## Why this project exists

It is the **reference implementation** of the repo's project layout. Every other
project (including your first Kaggle one) is a copy of `../_template/` with a
different `configs/config.yaml` and different notebooks. The pipeline is
deliberately small so the *process* is the thing you are learning.

> **Note:** the MLflow experiment was originally named `wine_quality_prediction`
> by the scaffold, which never matched the data. It is now
> `01_diabetes_regression`. The six older runs still exist under the old
> experiment name inside `mlflow.db`.

## Commands

Run from **this folder** (that is how DVC invokes the stages too):

```powershell
cd projects\01_diabetes_regression

python -m src.data      # regenerate data/processed/*.parquet
python -m src.train     # train, evaluate, log to MLflow, write models/model.pkl
pytest                  # smoke + data validation tests
```

Run from the **repo root** (shared services live there):

```powershell
.\.venv\Scripts\Activate.ps1
dvc repro -P                                    # every project's pipeline
dvc repro projects/01_diabetes_regression/dvc.yaml   # just this one
mlflow ui --port 5000                           # reads the shared ./mlflow.db
```

`mlflow ui` must run from the repo root — MLflow 3.x resolves `sqlite:///mlflow.db`
relative to the current directory, and `src/train.py` explicitly pins the shared
repo-level database so runs from every project land in the same UI.

## Exercises (the actual ML work)

1. **Baseline first.** Train a `DummyRegressor` (or plain `LinearRegression`) and
   log it. A RandomForest is meaningless until you know what "no skill" scores.
2. **Tune, don't guess.** Change `n_estimators` / `max_depth` / add
   `min_samples_leaf` in `configs/config.yaml`, re-run, and compare in the UI.
3. **Add a feature-importance look.** The `s5` (log of serum triglycerides)
   feature usually dominates. Confirm it in a notebook, then note the finding.
4. **Change the split protocol.** Try `KFold` cross-validation instead of a
   single hold-out split and compare the variance of your RMSE.
5. **Try a different model.** Gradient boosting or `HistGradientBoostingRegressor`
   — extend `build_model()` in `src/train.py` and log the new `model_type`.
6. **Graduate the project.** Milestones 3 and 4 in `ROADMAP.md` (FastAPI +
   Docker) are where this stops being a bare ML project.

Each experiment is one row in MLflow. Resist the urge to edit code to "make the
number look good" — log every attempt, including the failures.
